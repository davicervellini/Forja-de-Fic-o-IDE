## polish-01: Polish silently deletes legitimate [System] lines (drop_new_system_lines matches whole lines only)

- Impacto: medium | esforço: small | verificado: sim

**Evidência.** pipeline/scenes.py:301-305 builds `allowed` from original lines that START with "[System]" and deletes every output line that starts with [System] and is not an exact string match; orchestrator.py:404 applies it to every polished scene. In polish_input.md:3 and :15 the [System] messages are inline (…printed on its own beside him: “[System] Build progress: 0%.” / the prompt read: '[System] Help.'), so `allowed` is empty. gemma4 did what the style guide asks (05_refining.txt:28 "System boxes: on their own line") and moved them onto their own lines. The filter then removed both. Result: polish_gemma4_12b_t0.3.md:1 ends "He glanced down at the line the System had printed beside him:" and :17 ends "the prompt read:", with nothing after either colon. My per-scene count gives [System] 2 -> 0 for scene 1. results.jsonl:3 still reports rejected: 0, because refine_problems (scenes.py:370-392) never checks [System] lines. The gemma4 draft actually used today (04/05 prompts) has standalone lines such as "[System] Status: station not built, transport pending, Level Zero pending, materials 0, progress 0%." Any punctuation fix, re-quoting or joining by the polisher removes the line.

**Proposta.** Minimal fix first. (1) Rewrite drop_new_system_lines so that `allowed` is the set of normalized [System] spans found anywhere in the draft: regex `\[System\][^\n"“”'‘’]*`, then strip whitespace, surrounding quotes/backticks and trailing punctuation, and casefold. Keep an output [System] line when its normalized text is in that set. The existing test in tests/test_cenas.py:97-99 still passes. (2) In refine_problems, add `perdeu [System] (n -> m)` when the draft's normalized spans are not all present in the output, and do the same for command lines matching `^>\s*\w+`. Then repair: re-insert the missing span after the output line that ends with ':' or that contains the draft sentence before it. If there is no anchor, reject only that paragraph (see polish-06 paragraph revert). (3) Placeholders (⟦S1⟧) are optional. A 12B model may drop or wrap unusual markers, so only use them together with the validation in (2).

**Efeito esperado.** The chapter's few System boxes (a signature device of the genre, 'at most three per chapter') and the '> status/> help' beats can no longer disappear. The dangling-colon sentences disappear too. The polisher can also follow the 'own line' formatting rule safely.
